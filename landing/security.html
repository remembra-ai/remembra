Security

Your agents' memory, kept on a short leash.

A memory that every agent reads has to be careful about what goes in, who can read it back, and who wrote it. This is how Remembra handles each.

  1. Redacted

    Keys, tokens and other secrets are stripped out before anything is saved.

  2. Isolated

    Every account's memory is walled off, and project-scoped keys only see their own projects.

  3. Attributed

    Every handoff names the agent, session and time that wrote it, and whether its facts came from git or from the agent.

  4. Open

    The core is MIT-licensed open source. Read it, run it, host it yourself.

Handoffs and briefs

The relay passes work between agents, so it is built on the assumption that what one agent wrote may be wrong, or may try to steer the next one.

  • Redacted before storage. Every string in a handoff passes secret redaction and the server's PII policy, value by value. A blocked value is replaced with [REDACTED:pii]; a close is never rejected for it.
  • The raw transcript stays on your machine. Close-out reads git and, for Claude Code, the local session transcript, and sends only the facts it pulled out.
  • Briefs are data, not instructions. Everything another agent or tool recorded is wrapped in one untrusted-data block with a fixed preamble. Text inside it cannot close the block.
  • One trust policy for every line. The handoff, inbox messages, status values, linked projects' headlines and recent memories all pass the same check. When recorded text matches prompt-injection patterns (instruction overrides, requests to keep something from you, hidden Unicode characters), the brief shows a LOW TRUST marker and the id to review, not the text. This covers the brief's text and its JSON fields.
  • Commands are flagged, not trusted. Pipe-to-shell installs, base64 -d | sh, rm -rf, force pushes, skipped git hooks, permission-bypass flags, reads of ~/.ssh, .env or ~/.claude.json, and links outside your repository are marked confirm with the user before running. Markdown images are removed, so their URLs cannot carry data out.
  • Tool results are framed too. MCP tools that return stored content (recall, lists, the timeline, the inbox, the brief) wrap it in the same untrusted-data block, with the same escaping.
  • Inbox messages are redacted and scored. Secrets in a message's subject, body and metadata are removed before it is saved, and each message keeps its trust score. An inbox message is a request to confirm with you, never an instruction.
  • Graded, not taken on faith. Each handoff gets a health grade computed from its facts (Ready, Ready with warnings, Incomplete, Conflicted or Blocked) with what is missing, such as unpushed commits or tests that were not run. No language model is involved.
  • Attributed. A handoff closed with a key scoped to one agent is shown as key-verified, and that key cannot write as another agent. Otherwise it is shown as self-declared. An agent's own summary is marked unverified, or contradicted when the facts disagree.

Data protection

  • Encryption at rest: memory content and metadata in the vector store are encrypted with AES-256-GCM, and 2FA secrets are encrypted. The metadata database is not yet field-encrypted; we are extending encryption to all stored memory data.
  • Encryption in transit: all API traffic uses HTTPS.
  • User scoping: memories are strictly scoped to their account, preventing cross-account leakage.
  • PII detection: built-in detection and optional redaction of sensitive data.

Access control

  • Scoped API keys: keys can be limited to one agent, to certain projects, and to certain permissions.
  • Project-restricted keys can only resolve into, close, brief and see links for their own projects, and never move a repository's binding.
  • Roles: admin, editor and viewer roles for keys, and owner, admin, member and viewer roles for teams.
  • Rate limiting against abuse, per plan and per minute.
  • Audit logging of API operations.

Hosting

Self-hosted

Run Remembra on your own infrastructure with full control over your data. The hosted service is optional; a self-hosted server keeps your memory on your network.

Remembra Cloud

Our managed service is designed for secure operations, with audit logging, hardened defaults and deployment controls that support customer compliance reviews.

Compliance and privacy

  • Export and deletion: export your memories, or delete them, whenever you want.
  • No training on your data: your memories are never used to train AI models.

The privacy policy covers what we collect and why.

Responsible disclosure

If you find a security issue, please report it privately to security@dolphytech.com. We aim to respond within 48 hours and will work with you to understand and fix it.
